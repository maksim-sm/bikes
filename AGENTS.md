# AGENTS.md — правила работы ИИ-агентов над проектом `bikes`

Фронтенд интернет-магазина велосипедов для покупателей из Беларуси. Интерфейс на русском, валюта BYN.

**Источник истины — [`project-design-document.md`](./project-design-document.md)** (далее — ДД). Этот файл не заменяет ДД, а задаёт правила, как по нему работать. Если правило здесь расходится с ДД — следуй ДД и сообщи о расхождении.

---

## 1. Как работать

### 1.1. Перед началом задачи

1. Прочитай разделы ДД, относящиеся к задаче (страница — раздел 5, данные — 8, визуал — 7, Беларусь — 6).
2. Определи этап из раздела 15 ДД. Не реализуй функции более поздних этапов «заодно», если об этом не просили.
3. Посмотри существующий код: компоненты, утилиты, типы, токены. **Переиспользуй, а не дублируй.**
4. Если задача противоречит ДД или требует решения, которого в ДД нет (см. раздел 16 ДД) — задай один конкретный вопрос с рекомендуемым вариантом. По мелким обратимым решениям — действуй сам и упомяни их в итоге.

### 1.2. Во время работы

- Одна задача — одно логически завершённое изменение. Не делай попутных рефакторингов чужого кода без необходимости.
- Сначала типы и данные (`types/`, `data/`, `lib/api/`), потом UI.
- Новые зависимости — только если их нет в стеке ДД (раздел 2) и задачу нельзя решить имеющимися. Устанавливай пакет **до** того, как пишешь импортирующий его код.
- Не меняй ДД без явной просьбы. Если при реализации выяснилось, что ДД нужно уточнить, — предложи правку отдельно.

### 1.3. Завершение задачи

Задача считается готовой, только если:

- [ ] `tsc` без ошибок, линтер без ошибок, нет `any` и `@ts-ignore` без комментария-причины.
- [ ] Изменённые страницы проверены в браузере: мобильный (375 px) и десктоп (1280 px).
- [ ] Реализованы все состояния: загрузка, пусто, ошибка, успех (раздел 10 ДД).
- [ ] Нет строк интерфейса вне `lib/i18n/ru.ts`, нет «сырых» цветов вне токенов.
- [ ] Удалены отладочные `console.log`.
- [ ] Итоговое сообщение — 2–4 предложения: что сделано, как проверено, что осталось/какие допущения.

## 2. Стек (не отклоняться без согласования)

| Слой | Решение |
| --- | --- |
| Фреймворк | Next.js 16 App Router, React 19.2, TypeScript strict |
| Стили | Tailwind CSS v4, токены в `app/globals.css` (`@theme inline`) |
| UI | shadcn/ui (Radix), иконки `lucide-react` (16/20/24 px) |
| Данные | Server Components + SWR на клиенте |
| Формы | react-hook-form + zod |
| Уведомления | sonner |
| Изображения | `next/image` |

Запрещено: `localStorage` для сессии и токенов, `useEffect` для загрузки данных, CSS-модули/styled-components, сторонние UI-киты помимо shadcn, ORM и реальные БД (на этапе моков).

### Особенности Next.js 16

- `params`, `searchParams`, `cookies()`, `headers()` — асинхронные, всегда `await`.
- `middleware.ts` называется `proxy.ts`.
- `revalidateTag(tag, 'max')` — второй аргумент обязателен.
- Кеширование каталога — через `'use cache'` (при включённом `cacheComponents`).

## 3. Архитектура и код

### 3.1. Структура

Строго по разделу 9 ДД. Кратко:

```
app/            маршруты (URL — транслит, см. 3.1 ДД), app/api/* — мок-эндпоинты
components/ui   только shadcn-примитивы (не редактировать без нужды)
components/<домен>/  catalog, product, reviews, podbor, sizing, cart, checkout, account, layout
data/           мок-данные
lib/            api/, format.ts, sizing.ts, podbor.ts, validation.ts, i18n/ru.ts
types/          модели из 8.2 ДД
```

- Имена файлов — `kebab-case.tsx`, компоненты — `PascalCase`, один основной компонент на файл.
- `page.tsx` — тонкий: загрузка данных + композиция компонентов. Логику и разметку выносить в `components/`.
- Server Components по умолчанию. `'use client'` — только для интерактивных «листьев» (кнопки, фильтры, степперы), а не для целых страниц.

### 3.2. Данные и моки

- UI **никогда** не импортирует `data/*` напрямую — только через `lib/api/*` → `app/api/*`. Это гарантирует, что при подключении бэкенда UI не меняется.
- Контракты эндпоинтов — по таблице 8.3 ДД, типы — по 8.2. Меняешь тип — меняй его в `types/` и обновляй все использования.
- В dev-режиме моки имитируют задержку 200–600 мс и (по флагу) ошибки — не убирай это.
- Оплата — только через интерфейс `PaymentProvider`; мок и будущие bePaid/WEBPAY — его реализации.

### 3.3. Состояние

| Что | Где |
| --- | --- |
| Фильтры, сортировка, страница, ответы квиза | URL search params (ссылкой можно поделиться, работает «Назад») |
| Корзина | API + cookie-сессия гостя, SWR с оптимистичными обновлениями |
| Избранное, сравнение | Гость — локально; после входа — синхронизация через API |
| Сессия | httpOnly cookie; профиль — SWR `/api/account/me` |

Не дублируй серверное состояние в `useState`. Один SWR-ключ на ресурс, мутации — через `mutate`.

### 3.4. Деньги

- Суммы — **целые копейки** (`type Money = number`). Никаких `float` в расчётах.
- Форматирование — только `formatPrice()` из `lib/format.ts` → `1 249,00 р.`
- Итоги заказа и цены **пересчитываются на сервере** (в мок-API). Значения с клиента не доверяются; количество — целое, > 0, не больше остатка.

## 4. Язык и тексты

- Все строки интерфейса — в `lib/i18n/ru.ts`. Хардкод русских строк в JSX запрещён (кроме SEO-текстов, приходящих из данных).
- Склонения — через хелпер на `Intl.PluralRules('ru')`: «1 товар / 2 товара / 5 товаров». Никогда не писать «товар(ов)».
- Обращение на «вы» (строчная), тон дружелюбный и конкретный. Без канцелярита («осуществить оплату» → «оплатить»), без восклицательных знаков в каждой фразе.
- Используй «ё» там, где она есть: «колёса», «чёрный», «ещё», «подберём».
- Кавычки — «ёлочки», тире — «—», диапазоны — «3–5 дней» (короткое тире), неразрывный пробел перед «р.» и в числах.
- Тексты ошибок — что случилось и что делать: «Проверьте номер телефона: код оператора 25, 29, 33 или 44».
- Не выдумывай факты о магазине (сроки, гарантии, реквизиты). Используй значения из ДД или помечай как `TODO`-заглушки в одном месте (`lib/config.ts`).

## 5. Беларусь — обязательные требования

- Телефон: маска `+375 (XX) XXX-XX-XX`, допустимые коды — 25, 29, 33, 44. Схема — в `lib/validation.ts`.
- Индекс — 6 цифр. Регион — 6 областей + г. Минск.
- Даты — `ru-BY`, формат `ДД.ММ.ГГГГ` или «20 октября».
- Оплата — ровно три способа: «Оплата при получении» (`on_delivery`, одна опция — наличными или картой покупатель решает при получении, в UI не разделять), онлайн картой (Visa, Mastercard, БЕЛКАРТ), ЕРИП «Расчёт» — с номером счёта и инструкцией на странице успеха.
- Доставка — только курьер по Минску, курьер по Беларуси и самовывоз из магазина (раздел 6.2 ДД). Других способов доставки и пунктов выдачи не добавлять.
- Чекаут: **отдельный** чекбокс согласия на обработку персональных данных (Закон № 99-З), не отмечен по умолчанию, плюс согласие с публичным договором.
- Подвал: реквизиты продавца (наименование, УНП, адрес, регистрация в Торговом реестре) — из `lib/config.ts`, не хардкодом.
- Гарантия/возврат — с учётом того, что велосипед — технически сложный товар.

## 6. Визуальный дизайн

Направление — **«Мастерская»**: чистый технический стиль, фото велосипедов — главный элемент, интерфейс вокруг спокойный.

### 6.1. Цвета — строго 5 базовых

| Токен | Значение |
| --- | --- |
| `--background` | `#F4F5F2` |
| `--card` | `#FFFFFF` |
| `--foreground` | `#1B1E22` |
| `--primary` / `--accent` | `#1F3B63` (navy «Рама») |
| `--destructive` | `#B3261E` |

- Производные (`--primary-hover`, `--primary-soft`, `--muted`, `--border`, `--muted-foreground`, `--ring`, `--destructive-soft`) — только оттенки/прозрачности базовых, см. 7.2 ДД.
- **Запрещено**: жёлтый, оранжевый, зелёный и любые новые цвета; классы `bg-white`, `text-black`, `bg-blue-*` и hex в классах. Только семантические токены (`bg-primary`, `text-muted-foreground`, …).
- Navy — единственный акцент: основные кнопки, ссылки, активные состояния, бейдж скидки, звёзды рейтинга, «В наличии», успех.
- Красный — **только** ошибки и деструктивные действия. Не использовать для скидок и промо.
- Соответствие «задача → цвет» — по таблице «Цвета по задачам интерфейса» в 7.2 ДД. Новую задачу решай в той же логике, а не новым цветом.
- Статус никогда не передаётся только цветом: всегда иконка + текст.
- Если меняешь фон компонента — явно задай и цвет текста. Контраст ≥ 4.5:1.
- На `<html>` — класс `bg-background`.

### 6.2. Типографика

- Только два шрифта: **Unbounded** (заголовки H1–H3, цены, названия категорий) и **Onest** (всё остальное). `next/font/google`, `subsets: ['cyrillic', 'latin']`.
- Применять через классы `font-heading` / `font-sans` (переменные `--font-heading` и `--font-sans` объявлены в `@theme inline` в `globals.css`), не через `style`.
- Основной текст 16 px, минимум 14 px, `leading-relaxed`. Заголовки — `text-balance`. Числа в таблицах — `tabular-nums`.

### 6.3. Вёрстка

- Mobile-first. Сетка каталога: 2 → 3 (`lg`) → 4 (`xl`) колонки, контейнер до 1360 px.
- Flexbox по умолчанию, Grid — для двумерных сеток. Без `float`, `absolute` — только когда без него никак.
- Шкала Tailwind вместо произвольных значений (`p-4`, не `p-[17px]`). Промежутки — `gap-*`; не смешивать `gap` и `margin` на одном элементе; не использовать `space-*`.
- Скругления: карточки `--radius` (0.5rem), кнопки 0.375rem.
- Зона нажатия ≥ 44×44 px.
- Анимация сдержанная, всегда с учётом `prefers-reduced-motion`.

### 6.4. Анти-паттерны (не делать)

- Градиенты, «светящиеся» пятна, декоративные блобы.
- Карточки с цветной полосой слева.
- Выдуманная статистика («10 000+ довольных клиентов») и декоративные иконки без смысла.
- Эмодзи в интерфейсе вместо иконок.
- Заглушки изображений — генерировать реальные фото товаров (4:3, светлый однородный фон).

## 7. Доступность (WCAG 2.1 AA)

- Семантика: `header`, `nav`, `main`, `footer`, один `h1` на страницу, иерархия заголовков без пропусков.
- Всё доступно с клавиатуры; видимый фокус `--ring`; ссылка «Перейти к содержимому».
- `alt` у фото товара — описательный: «Горный велосипед Merida Big.Nine 300, чёрный, вид сбоку». Декоративные — `alt=""`.
- Иконки-кнопки — с `aria-label` или `sr-only`-текстом.
- Свотчи цветов — с текстовым названием.
- Ошибки форм — текстом рядом с полем + `aria-describedby` + `aria-invalid`.
- Счётчик корзины, результаты фильтров, тосты — через `aria-live`.
- Отправка по Enter: не отправлять при `e.nativeEvent.isComposing || e.keyCode === 229`.

## 8. SEO и производительность

- `generateMetadata` для категорий и товаров: title по шаблону из 12 ДД, description, Open Graph, canonical. `lang="ru"`.
- JSON-LD: `Product` (цена в BYN, наличие, рейтинг), `BreadcrumbList`, `Organization`, `Review`.
- Страницы с произвольными комбинациями фильтров — `noindex`; посадочные (бренд + категория) — индексируются.
- Бюджеты: LCP < 2.5 с, INP < 200 мс, CLS < 0.1, JS первой загрузки < 200 КБ gzip.
- `next/image` всегда с размерами/`sizes`; `priority` — только у первого изображения экрана.
- Тяжёлое (карусели, отзывы, галерея-зум, диалоги) — ленивая загрузка.
- Скелетоны повторяют форму контента, чтобы не было сдвигов.

---

## 9. Безопасность

- Сессия — httpOnly, Secure, SameSite cookie. Никаких токенов и персональных данных в `localStorage`.
- Одни и те же zod-схемы на клиенте и в мок-API.
- Не логировать и не выводить персональные данные покупателя.
- Заголовки безопасности — в `next.config` (`headers()`), по разделу 14 ДД; CSP — сначала Report-Only.
- Секреты — только через переменные окружения, никогда в коде и коммитах.

---

## 10. Git

- Работа — в ветках `v0/<краткое-описание>`. Прямой push в `main` — только по явной просьбе.
- Сообщения коммитов — в повелительном наклонении, кратко: «Добавить фильтры каталога», «Исправить маску телефона».
- Один коммит — одно логическое изменение. Не коммитить скриншоты, `.env*`, отладочные файлы.

## 11. Чек-лист ревью компонента

- [ ] Server или Client — выбрано осознанно, `'use client'` на минимальном поддереве.
- [ ] Данные — через `lib/api`, не напрямую из `data/`.
- [ ] Строки — из `ru.ts`, склонения — через хелпер, цены — через `formatPrice`.
- [ ] Только токены из 6.1, статус — иконка + текст.
- [ ] Состояния загрузки / пусто / ошибка / успех.
- [ ] Клавиатура, фокус, `alt`, `aria-*`.
- [ ] Мобильный и десктоп проверены в браузере.
