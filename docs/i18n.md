# Localization

Status: authoritative companion to ADR-0009 and ADR-0033.

The store is Russian for a Belarusian market. Domain modules return codes and
structured data. `app/` and `lib/i18n` turn those into language, money, dates,
and mail.

## Where copy lives

| Surface       | Catalogue                     | Notes                                              |
| ------------- | ----------------------------- | -------------------------------------------------- |
| UI            | `src/lib/i18n/messages/ru.ts` | No customer-facing string in a component           |
| Validation    | `form.*`, `validation.*`      | Checkout forms and Zod at the HTTP boundary        |
| System / HTTP | `errors.*`                    | Mapped from `AppError.code`, never from stack text |
| Emails        | `email.*`                     | Subject, preview, text; HTML is escaped text       |
| Notifications | `notifications.*`             | In-app titles/bodies keyed by stable codes         |
| Metadata      | `site.*`, `meta.*`            | Title template, Open Graph locale                  |
| Plurals       | `plural.*`                    | `one` / `few` / `many` for `Intl.PluralRules`      |

Product names and descriptions stay in the catalogue tables (`locale` column,
default `ru`). They are content, not UI chrome.

## Formatting

All display formatting goes through `src/lib/i18n`. `ru` uses `ru-BY`, currency
`BYN`, timezone `Europe/Minsk`.

- `formatPrice` — integer kopeks → Belarusian ruble string
- `formatNumber` — grouping and decimal rules
- `formatDate` / `formatTime` / `formatDateTime` — Minsk civil time
- `formatStoreDateTime` — same, plus a visible zone label («Минск»)
- `formatPlural` — Russian three-form plurals (`1 штука`, `2 штуки`, `5 штук`)

Do not concatenate `" " + amount` or `"мес."` onto a raw number.

## Emails

`renderEmail(kind, vars)` builds subject and text from the catalogue.
`emailActionUrl` puts a one-time token only in the customer-facing URL. The
logging mailer records `email` and `subject`, never the token or the URL.

Kinds today: `verify`, `passwordReset`, `orderPlaced`, `paymentFailed`,
`shipmentShipped`. A provider adapter later sends `text` / `emailHtml`.

## Notifications

`notificationCopy(code, vars)` is the in-app counterpart. Codes are dotted
English identifiers (`order.placed`). The checkout confirmation page already
renders `order.placed`.

## Adding a language

1. Add a row to `localeMeta` and `SUPPORTED_LOCALES` in `src/lib/i18n/locale.ts`.
2. Add `src/lib/i18n/messages/<locale>.ts` that satisfies `Messages`.
3. Register it in the `catalogues` map and in `APP_LOCALE`.
4. Do **not** add `/[locale]/` routing, a switcher, or `hreflang` until the
   business commits to that language (ADR-0009).

`resolveLocale` already falls back to `ru`.
